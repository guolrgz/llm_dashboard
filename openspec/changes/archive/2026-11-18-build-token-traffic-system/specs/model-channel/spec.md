# Spec Delta

## Purpose

管理推理网关背后的上游模型渠道，包括模型标识、供应商、上游地址、计费单价、启用状态与流量权重，为流量路由和成本统计提供依据。

## ADDED Requirements

### Requirement: 模型渠道目录

系统 SHALL 维护可接入模型渠道清单，每个渠道包含名称、供应商、上游地址、输入/输出单价（每 1K Token）、启用状态、流量权重；首次初始化 SHALL 内置 4 个渠道。

#### Scenario: 模型列表
- **WHEN** 具备 `models.view` 权限的用户调用 `GET /api/models`
- **THEN** 返回 `200`，默认包含 GPT-4o、Claude-3.5、Qwen-Max 与 1 个其他模型，且渠道密钥以掩码形式返回

#### Scenario: 无权限查看模型
- **WHEN** 不具备 `models.view` 权限的用户调用模型列表接口
- **THEN** 返回 `403`

### Requirement: 模型渠道维护

系统 SHALL 支持创建、编辑、启用/停用和删除模型渠道；模型名称必须唯一；停用或删除的模型 SHALL 不再参与网关路由，但历史请求日志与统计必须保留。

#### Scenario: 新增模型渠道
- **WHEN** 具备 `models.manage` 权限的用户提交唯一模型名称、供应商与单价创建渠道
- **THEN** 返回 `201`，新渠道出现在模型列表中且状态为启用

#### Scenario: 停用模型
- **WHEN** 管理员停用一个模型渠道后，网关收到该模型的推理请求
- **THEN** 返回 `400` 或 `404` 表示模型不可用，且不产生该模型的计费记录

#### Scenario: 模型名称重复
- **WHEN** 创建模型时提交已存在的模型名称
- **THEN** 返回 `409`，渠道不被写入

### Requirement: 模型流量权重

系统 SHALL 为每个启用的模型提供流量权重；网关在未显式指定模型时按权重选择模型；权重为非负整数，且系统概览的“接入模型”数量等于启用渠道数。

#### Scenario: 未指定模型时按权重路由
- **WHEN** 推理请求未指定模型，且存在多个启用渠道
- **THEN** 网关从启用渠道中按权重选择一个模型，并在响应与请求日志中记录实际使用的模型

#### Scenario: 概览接入模型数
- **WHEN** 客户端读取 Dashboard 系统概览
- **THEN** “接入模型”值等于启用中的模型渠道数量
